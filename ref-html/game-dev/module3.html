03.01

Coordinate Spaces

Every position in a game scene is expressed relative to some frame of reference. That frame is called a coordinate space. There is no single "correct" space — positions only have meaning when you know which space they are measured in.

Three spaces appear everywhere in game development:

Space Origin Axes Used for
Local / Object Object center Aligned to object Vertex positions in mesh data
World Scene origin Fixed, global Object placement in scene
Screen / NDC Center or top-left Pixel or [-1,1] Final rasterization

A 2D character mesh is stored in local space — vertices positioned around (0,0). When you place that character at position (300, 200) in the scene, you are expressing a transform from local space to world space. The camera then maps world space to screen space for rasterization.

Practical Rule
If a number feels wrong — a position that should be (0,0) appearing somewhere else, or a rotation that seems off-center — the first question to ask is: which coordinate space am I in? Most transform bugs are space confusion.
03.02

Affine Transformations

An affine transformation is any transformation that preserves straight lines and the ratio of distances along those lines. The three fundamental affine transforms are translation, rotation, and scale. Their defining property: parallel lines remain parallel after the transform.

In 2D, each transform operates on a point (x, y). The homogeneous coordinate trick adds a third component (w = 1) so that all three operations — including translation — can be expressed as matrix multiplication. Without homogeneous coordinates, translation cannot be a matrix operation. 

# 2D homogeneous point: [x, y, 1]
# All transforms become 3×3 matrix multiplications

# Translation by (tx, ty)
T = [[1, 0, tx],
     [0, 1, ty],
     [0, 0,  1]]

# Rotation by angle θ (counter-clockwise)
R = [[cos(θ), -sin(θ), 0],
     [sin(θ),  cos(θ), 0],
     [      0,        0, 1]]

# Scale by (sx, sy)
S = [[sx,  0, 0],
     [ 0, sy, 0],
     [ 0,  0, 1]]python

03.03

Matrix Multiplication

Applying a transform to a point means multiplying a 3×3 matrix by a 3×1 column vector. Each output component is the dot product of a row of the matrix with the input vector. 

# Matrix-vector multiply: M @ point
def mat_vec(M, p):
    x = M[0][0]*p[0] + M[0][1]*p[1] + M[0][2]*p[2]
    y = M[1][0]*p[0] + M[1][1]*p[1] + M[1][2]*p[2]
    w = M[2][0]*p[0] + M[2][1]*p[1] + M[2][2]*p[2]
    return [x, y, w]

# In practice, use numpy:
import numpy as np
result = M @ np.array([x, y, 1.0])python

Order Matters
Matrix multiplication is not commutative. T × R ≠ R × T. Rotating first then translating gives a different result than translating first then rotating. In game engines, the convention is almost always Scale → Rotate → Translate (applied right to left). The demos below make this concrete.
03.04

Combining Transforms

The power of matrix representation: applying ten transforms to a thousand vertices requires multiplying the ten matrices together once to produce a single combined matrix, then multiplying each vertex by that one matrix. The cost is ten matrix multiplications plus one thousand matrix-vector multiplications, instead of ten million. 

import numpy as np

def translation(tx, ty):
    return np.array([[1,0,tx],[0,1,ty],[0,0,1]], dtype=float)

def rotation(angle_deg):
    t = np.radians(angle_deg)
    c, s = np.cos(t), np.sin(t)
    return np.array([[c,-s,0],[s,c,0],[0,0,1]], dtype=float)

def scale(sx, sy):
    return np.array([[sx,0,0],[0,sy,0],[0,0,1]], dtype=float)

# Combine: S, then R, then T  (applied right-to-left)
M = translation(100, 50) @ rotation(45) @ scale(2, 2)

# Apply to all vertices at once (each row is a homogeneous point)
verts = np.array([[0,0,1],[1,0,1],[0,1,1]], dtype=float)
transformed = (M @ verts.T).Tpython

03.05

Hierarchical Transforms

A parent-child relationship means: the child's world transform is the parent's world transform multiplied by the child's local transform. Moving or rotating the parent automatically moves and rotates everything attached to it.

This is how all game engines organize scenes: a character's hand is a child of the forearm, which is a child of the upper arm, which is a child of the torso. Animating the shoulder moves the entire arm. The math is just matrix multiplication down the chain. 

# Traverse a scene graph, accumulating transforms
def get_world_transform(node, parent_world=None):
    if parent_world is None:
        parent_world = np.eye(3)
    world = parent_world @ node.local_transform
    for child in node.children:
        get_world_transform(child, world)
    node.world_transform = worldpython

Scene Graphs vs ECS
The hierarchical approach above is called a scene graph. It is intuitive but has performance costs as scenes grow. Module 10 introduces the Entity-Component-System (ECS) architecture, which separates data from hierarchy and is used by most modern engines.
03.06

Practical Work

Build a small matrix math library, then use it to animate a shape through a sequence of transforms.

Exercise 1 · Matrix Library 
import numpy as np
import math

class Transform2D:
    def __init__(self):
        self.m = np.eye(3, dtype=float)  # identity

    def translate(self, tx, ty):
        T = np.array([[1,0,tx],[0,1,ty],[0,0,1]], dtype=float)
        self.m = self.m @ T
        return self  # fluent API

    def rotate(self, degrees):
        r = math.radians(degrees)
        c, s = math.cos(r), math.sin(r)
        R = np.array([[c,-s,0],[s,c,0],[0,0,1]], dtype=float)
        self.m = self.m @ R
        return self

    def scale(self, sx, sy=None):
        sy = sy if sy is not None else sx
        S = np.array([[sx,0,0],[0,sy,0],[0,0,1]], dtype=float)
        self.m = self.m @ S
        return self

    def apply(self, points):
        # points: (N, 2) array → returns (N, 2)
        h = np.hstack([points, np.ones((len(points),1))])
        out = (self.m @ h.T).T
        return out[:, :2]

# Usage:
t = Transform2D().scale(2).rotate(45).translate(100, 50)
transformed_verts = t.apply(original_verts)python
