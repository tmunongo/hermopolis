09.01

Axis-Aligned Bounding Boxes

An Axis-Aligned Bounding Box (AABB) is a rectangle whose sides are parallel to the world axes — it cannot rotate. It is the simplest and fastest collision shape in 2D. Nearly all platform games use AABBs for their primary collision geometry.

Overlap between two AABBs is detected by the Separating Axis Theorem (SAT) applied to rectangles: two AABBs do not overlap if and only if there is a gap on at least one axis. If there is no gap on either axis, the boxes overlap. 

from dataclasses import dataclass

@dataclass
class AABB:
    x: float   # left edge
    y: float   # top edge
    w: float   # width
    h: float   # height

    @property
    def right(self):  return self.x + self.w
    @property
    def bottom(self): return self.y + self.h
    @property
    def cx(self):     return self.x + self.w / 2
    @property
    def cy(self):     return self.y + self.h / 2

def aabb_overlap(a: AABB, b: AABB) -> bool:
    # True if no separating axis exists in x OR y
    return (a.x < b.right  and
            a.right > b.x   and
            a.y < b.bottom  and
            a.bottom > b.y)python

The Minimum Translation Vector (MTV) is the smallest displacement to push the boxes apart. It is the overlap on the axis with the smallest penetration depth.
Why AABB?
Checking two AABBs requires exactly four comparisons — four subtractions and four conditional checks. Modern CPUs can evaluate millions of these per second. More complex shapes (convex polygons, capsules) require more computation. AABB is always the first broadphase check, even when a finer shape test follows.
09.02

Collision Resolution

Detecting a collision tells you that two objects are overlapping. Resolution fixes it: separate the objects so they no longer overlap, and adjust their velocities so future movement is physically plausible.

The MTV (Minimum Translation Vector) tells you the direction and distance to push objects apart. For a one-sided collision (static platform vs dynamic character), only the dynamic body moves. For two dynamic bodies, each moves by half the MTV. 

def get_mtv(a: AABB, b: AABB):
    """Returns (dx, dy) to push A out of B. Returns None if no overlap."""
    if not aabb_overlap(a, b):
        return None

    # Penetration depth on each axis
    overlap_x = min(a.right, b.right) - max(a.x, b.x)
    overlap_y = min(a.bottom, b.bottom) - max(a.y, b.y)

    # Resolve on the axis of least overlap
    if overlap_x < overlap_y:
        sign = 1 if a.cx < b.cx else -1
        return (-overlap_x * sign, 0)
    else:
        sign = 1 if a.cy < b.cy else -1
        return (0, -overlap_y * sign)

def resolve_aabb(dynamic, static, restitution=0.3):
    mtv = get_mtv(dynamic, static)
    if mtv is None: return
    dx, dy = mtv

    # Separate: push dynamic body out
    dynamic.x += dx
    dynamic.y += dy

    # Velocity response: reflect the component along the MTV axis
    if dx != 0: dynamic.vx *= -restitution
    if dy != 0: dynamic.vy *= -restitutionpython

Restitution e controls bounciness. e=0 is perfectly inelastic (no bounce), e=1 is perfectly elastic (full energy preserved). Most game objects use e≈0.3–0.6.
Tunnelling
A fast-moving object can travel through a thin wall in a single frame if its displacement is larger than the wall's thickness. Detection only runs at discrete frames, so it never catches the intermediate overlap. The fix is continuous collision detection (CCD): sweep the object's shape along its trajectory and find the first moment of contact. For game prototypes, clamping maximum velocity is simpler.
09.03

Circle Collisions

Circles are the second fundamental collision shape. The overlap test requires only a single distance calculation, and resolution is elegant: push the circles apart along the line connecting their centres. 

import math

def circle_overlap(ax, ay, ar, bx, by, br):
    """Returns (overlap_dist, nx, ny) or None if no overlap.
    nx, ny is the collision normal pointing from B toward A."""
    dx   = ax - bx
    dy   = ay - by
    dist = math.sqrt(dx*dx + dy*dy)
    if dist == 0: dx, dy, dist = 1, 0, 1  # coincident: arbitrary axis
    sum_r = ar + br
    if dist >= sum_r: return None
    overlap = sum_r - dist
    nx, ny  = dx / dist, dy / dist      # unit normal
    return overlap, nx, ny

def resolve_circles(a, b, restitution=0.8):
    result = circle_overlap(a.x, a.y, a.r, b.x, b.y, b.r)
    if result is None: return
    overlap, nx, ny = result

    # Separate: push each body out by half the overlap
    a.x += nx * overlap / 2
    a.y += ny * overlap / 2
    b.x -= nx * overlap / 2
    b.y -= ny * overlap / 2

    # Velocity: reflect relative velocity along collision normal
    rel_vx = a.vx - b.vx
    rel_vy = a.vy - b.vy
    dot    = rel_vx * nx + rel_vy * ny   # relative speed along normal

    if dot > 0: return   # already separating

    impulse = -(1 + restitution) * dot / 2   # equal mass assumption
    a.vx += impulse * nx;  a.vy += impulse * ny
    b.vx -= impulse * nx;  b.vy -= impulse * nypython

09.04

Kinematics and Euler Integration

Physics simulation moves objects by integrating their equations of motion over time. The simplest integrator is Euler integration: apply acceleration to velocity, then apply velocity to position — one timestep at a time. 

def integrate(body, dt, gravity=600):
    # 1. Apply forces to velocity
    body.vy += gravity * dt          # gravity is a constant downward force
    body.vx += body.ax * dt          # ax = sum of other horizontal forces / mass
    body.vy += body.ay * dt

    # 2. Apply velocity to position
    body.x += body.vx * dt
    body.y += body.vy * dt

    # 3. Apply drag (optional: approximates air resistance)
    body.vx *= (1 - body.drag * dt)
    body.vy *= (1 - body.drag * dt)python

Symplectic Euler
Standard Euler (update velocity, then use old velocity to update position) has a systematic energy gain error that causes orbits to spiral outward. Symplectic Euler (update velocity first, then use new velocity to update position) is energy-conserving and only requires swapping two lines. For game physics this is always the right choice. 
# Standard Euler — energy drifts upward (wrong)
old_vx = body.vx
body.x  += old_vx * dt     # uses OLD velocity
body.vx += ax * dt

# Symplectic Euler — energy stable (correct)
body.vx += ax * dt         # update velocity FIRST
body.x  += body.vx * dt    # then use NEW velocitypython
09.05

Forces, Gravity, and Friction

All motion in a physics simulation is driven by forces. A force applied to a body accelerates it: a = F / m. Multiple forces add as vectors. Gravity is a constant downward force. Friction is a force opposing motion — proportional to the normal force and a friction coefficient. 

class PhysicsBody:
    def __init__(self, x, y, mass=1.0):
        self.x, self.y   = x, y
        self.vx, self.vy = 0, 0
        self.mass        = mass
        self.inv_mass    = 1.0 / mass   # precomputed for speed
        self._fx, self._fy = 0, 0      # accumulated force this frame

    def apply_force(self, fx, fy):
        self._fx += fx
        self._fy += fy

    def integrate(self, dt, gravity=980):
        self._fy += gravity * self.mass   # gravity = force × mass
        ax = self._fx * self.inv_mass
        ay = self._fy * self.inv_mass
        self.vx += ax * dt               # symplectic Euler
        self.vy += ay * dt
        self.x  += self.vx * dt
        self.y  += self.vy * dt
        self._fx = self._fy = 0         # clear forces for next frame

    def apply_friction(self, mu_k, normal_force, dt):
        # Kinetic friction opposes velocity direction
        speed = (self.vx**2 + self.vy**2)**0.5
        if speed < 0.01: return
        friction_mag = mu_k * normal_force
        self._fx -= (self.vx / speed) * friction_mag
        self._fy -= (self.vy / speed) * friction_magpython

Broad Phase + Narrow Phase
Checking every pair of N bodies is O(N²). For large scenes, this is too slow. Real physics engines use a broad phase — a fast cheap filter (spatial hashing, BVH trees) — to produce a short list of candidate pairs. Only those pairs get the expensive narrow-phase test. For the sizes in this module, O(N²) is fine.
