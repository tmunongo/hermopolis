04.01

The GPU Pipeline (Revisited)

Module 2 introduced the rendering pipeline conceptually. Now we are operating it directly. The GPU pipeline is not automatic — you configure each stage by uploading data and binding programs. Understanding which stages are programmable versus fixed-function determines what you control and what the hardware handles.

The two stages you write code for are the vertex shader and the fragment shader. Everything else is handled by fixed hardware. This is why the API for GPU rendering feels like: set up data, write two programs, issue a draw call.

04.02

Vertex Buffers (VBOs)

A Vertex Buffer Object (VBO) is a block of GPU memory that holds raw vertex data. Before any triangle can be drawn, its vertex data must exist in GPU memory. You pack it on the CPU as a flat byte array and upload it once.

Vertex data is interleaved: each vertex's attributes are packed together sequentially. For a triangle with positions and colors, each vertex contributes five floats — two for position, three for color.

import numpy as np
import moderngl

# Triangle: 3 vertices, each with [x, y, r, g, b]
vertices = np.array([
    #  x      y     R     G     B
     0.0,  0.8, 1.0, 0.0, 0.0,   # top — red
    -0.8, -0.5, 0.0, 1.0, 0.0,   # bottom-left — green
     0.8, -0.5, 0.0, 0.0, 1.0,   # bottom-right — blue
], dtype='f4')

ctx = moderngl.create_standalone_context()

# Upload to GPU — ctx.buffer() copies the bytes
vbo = ctx.buffer(vertices.tobytes())python + moderngl


				

					Notice that the data is in normalized device coordinates (NDC): x and y in the
					range [-1, 1]. The center of the screen is (0, 0). The GPU's rasterizer works in this
					coordinate system by default. In later modules, a transform matrix maps from world
					coordinates to NDC.
				


				

					
Float Format

					GPU buffers use 32-bit floats (f4 / GL_FLOAT), not Python's
					64-bit doubles. Always specify dtype='f4' in NumPy. Passing 64-bit data will
					silently produce incorrect results as the GPU interprets the bytes as f32.
				

			


			
			

				

					04.03
					
Vertex Array Objects (VAOs)

				


				

					A VBO contains raw bytes. The GPU has no idea how to interpret them — it doesn't know
					where one vertex ends and another begins, or which bytes are positions versus colors. A
					Vertex Array Object (VAO) provides that layout description.
				

				

					The VAO stores: which VBO to read from, the byte offset and stride of each attribute, and
					which shader input each attribute maps to.

# The format string '2f 3f' means:
#   first attribute:  2 floats (8 bytes)  → position
#   second attribute: 3 floats (12 bytes) → color
# moderngl reads them interleaved: [x,y,r,g,b] [x,y,r,g,b] ...

program = ctx.program(
    vertex_shader="""
        #version 330
        in vec2 in_position;
        in vec3 in_color;
        out vec3 v_color;
        void main() {
            gl_Position = vec4(in_position, 0.0, 1.0);
            v_color = in_color;
        }
    """,
    fragment_shader="""
        #version 330
        in vec3 v_color;
        out vec4 out_color;
        void main() {
            out_color = vec4(v_color, 1.0);
        }
    """
)

# VAO: link VBO → program inputs, with layout '2f 3f'
vao = ctx.vertex_array(program, [(vbo, '2f 3f', 'in_position', 'in_color')])python + moderngl


				

					
OpenGL State Machine

					OpenGL operates as a global state machine. Objects like VBOs and VAOs are created, given
					integer IDs, and must be bound (made current) before operations apply to them.
					The VAO stores which VBO was bound when attributes were configured — so binding the VAO
					later automatically restores that relationship.

					04.04
					
Shader Programs

				


				

					A shader program is a pair of GPU programs — vertex and fragment —
					compiled and linked together. In moderngl this is done in a single
					ctx.program() call. The shaders are written in GLSL (OpenGL Shading
					Language), which has a C-like syntax.
				

				

					Data flows from the CPU through the pipeline in three ways:
					attributes (per-vertex data from the VBO), uniforms (constant values set
					by the CPU, same for every vertex), and varyings (values passed from the vertex
					shader to the fragment shader, interpolated across the triangle).
				


				
				

					

						Interactive · Shader Data Flow

					04.05
					
The Draw Call

				


				

					A draw call is the instruction that tells the GPU to start processing
					geometry. It specifies the VAO to read from, the primitive type, and how many vertices to
					process. Everything before the draw call is setup — data uploads, state binding, uniform
					setting. The draw call is what launches the pipeline.
				


				
# The complete sequence for one frame:

# 1. Clear the framebuffer
ctx.clear(0.07, 0.07, 0.12)

# 2. Update uniforms (e.g., a transform that changes each frame)
program['u_transform'].value = tuple(M.flatten())

# 3. Issue the draw call — TRIANGLES, starting at vertex 0, 3 vertices
vao.render(moderngl.TRIANGLES)python + moderngl


				

					The draw call is deceptively small. Behind those three lines: the GPU reads all vertex
					data, runs the vertex shader on every vertex in parallel, rasterizes the resulting
					triangles, runs the fragment shader on every covered pixel in parallel, and writes the
					results to the framebuffer. For a large mesh that may be millions of operations — all
					launched by a single call.
				


				

					
Draw Call Overhead

					Each draw call has CPU-side overhead — state validation, command encoding, driver work.
					Games try to minimize the number of draw calls per frame. A scene with 1000 objects that
					each require a separate draw call performs much worse than one that batches geometry into
					a single call. This motivates techniques like geometry batching, instancing, and atlasing.

						Exercise 1 · The Minimum GPU Triangle
					

					
The complete moderngl program from context creation to saving the output image:

					
import numpy as np
import moderngl
from PIL import Image

# 1. Create a headless (no window) OpenGL context
ctx = moderngl.create_standalone_context()

# 2. Vertex data: x, y, r, g, b — 3 vertices in NDC
vertices = np.array([
     0.0,  0.8, 0.22, 0.74, 0.97,
    -0.8, -0.5, 0.97, 0.36, 0.22,
     0.8, -0.5, 0.29, 0.86, 0.50,
], dtype='f4')

# 3. Upload to GPU
vbo = ctx.buffer(vertices.tobytes())

# 4. Compile shaders + create program
program = ctx.program(
    vertex_shader="""
        #version 330
        in vec2 in_position;
        in vec3 in_color;
        out vec3 v_color;
        void main() {
            gl_Position = vec4(in_position, 0.0, 1.0);
            v_color = in_color;
        }
    """,
    fragment_shader="""
        #version 330
        in vec3 v_color;
        out vec4 out_color;
        void main() { out_color = vec4(v_color, 1.0); }
    """
)

# 5. Create VAO: link VBO to program attributes
vao = ctx.vertex_array(program, [(vbo, '2f 3f', 'in_position', 'in_color')])

# 6. Create a framebuffer to render into (512×512)
fbo = ctx.simple_framebuffer((512, 512))
fbo.use()

# 7. Render
ctx.clear(0.07, 0.07, 0.12)
vao.render(moderngl.TRIANGLES)

# 8. Read pixels back to CPU and save
data = fbo.read(components=3)
img = Image.frombytes('RGB', fbo.size, data, 'raw', 'RGB', 0, -1)
img.save('triangle.png')python + moderngl

						Exercise 2 · Rotating Triangle with a Uniform Matrix
					

					

						The vertex shader applies a rotation matrix passed from Python. The matrix changes each
						frame, giving the illusion of motion.
					

					
import numpy as np
import moderngl, math

def rotation_matrix(angle_deg):
    r = math.radians(angle_deg)
    c, s = math.cos(r), math.sin(r)
    return np.array([
        c, -s, 0,
        s,  c, 0,
        0,  0, 1
    ], dtype='f4')

# Vertex shader reads a mat3 uniform
vertex_src = """
    #version 330
    uniform mat3 u_transform;
    in vec2 in_position;
    in vec3 in_color;
    out vec3 v_color;
    void main() {
        vec3 p = u_transform * vec3(in_position, 1.0);
        gl_Position = vec4(p.xy, 0.0, 1.0);
        v_color = in_color;
    }
"""

# Each frame: update the angle and re-upload the matrix
angle = 0.0
while running:
    angle += 1.5  # degrees per frame
    M = rotation_matrix(angle)
    program['u_transform'].value = tuple(M)
    ctx.clear(0.07, 0.07, 0.12)
    vao.render(moderngl.TRIANGLES)
    window.swap_buffers()python + moderngl
