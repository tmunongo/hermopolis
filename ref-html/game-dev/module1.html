01.01

What is a Pixel?

The word pixel is a contraction of picture element. A pixel is the smallest addressable unit in a raster image. Every digital image you have ever seen — on a phone screen, in a browser, in a game — is a rectangular grid of pixels, each assigned a color value.

When you look at a high-resolution photograph, you perceive continuous tone: smooth gradients, sharp edges, fine detail. That perception is an illusion of density. Zoom in far enough and the grid becomes visible. This is the fundamental nature of raster images: they are discrete, not continuous.

Definition
A pixel has no inherent physical size. It is simply a position in a grid with an associated color. Physical size depends on the output device: a 100×100 image displayed at 96 dpi looks different than the same image at 300 dpi.

The number of pixels in an image is its resolution. A 1920×1080 image contains exactly 2,073,600 pixels. This is the quantity that determines how much detail the image can represent — not its file size, and not its physical dimensions.

01.02

Color Models: RGB, RGBA, and Formats

A color model defines how color is represented numerically. The dominant model in game development and computer graphics is RGB: three channels, one each for red, green, and blue. By combining different intensities of these three primaries, every visible color can be approximated.

In the most common representation, each channel is stored as an 8-bit unsigned integer, giving 256 possible values per channel (0–255). Three channels give you 256³ = 16,777,216 possible colors. This is commonly written as uint8 format.

Format Channels Bits per pixel Use case
RGB8 R, G, B 24 Standard opaque images
RGBA8 R, G, B, A 32 Images with transparency
R8 (Grayscale) L 8 Heightmaps, masks
RGB16F R, G, B 48 HDR rendering
RGBA32F R, G, B, A 128 Floating point framebuffers

The alpha channel (A) represents opacity. A value of 255 means fully opaque; 0 means fully transparent. Alpha is used extensively in game development for sprite rendering, UI overlays, and compositing effects.

Note that some systems normalize color values to the range [0.0, 1.0] as floating point, rather than [0, 255] as integers. GPU shaders always work in the normalized range. You will convert frequently between the two.

Common Confusion
RGB is an additive color model — mixing all three channels at full intensity gives white, not black. This is the opposite of paint mixing (subtractive). In games, mixing lights and colors on screen always follows additive rules.
01.03

Image Memory Layout

Images are stored in memory as a flat, one-dimensional array of bytes. There is no inherent two-dimensionality in RAM. The 2D structure is a convention: rows of pixels are packed sequentially, and software applies a formula to locate any pixel by its (x, y) coordinates.

For an image with width W and height H in RGBA format (4 bytes per pixel), the byte offset of pixel at column x, row y is: 

# byte offset of pixel (x, y) in an RGBA image
offset = (y * W + x) * 4

# the four channel bytes at that offset:
R = image_data[offset + 0]
G = image_data[offset + 1]
B = image_data[offset + 2]
A = image_data[offset + 3]python

This row-major ordering means that iterating across columns (increasing x) is cache-friendly — consecutive pixels are adjacent in memory. Iterating down rows (increasing y) jumps by W × bytes_per_pixel each step.

NumPy represents images as arrays of shape (H, W, C) — height, width, channels. This means image[y, x] gives the pixel at row y, column x. The channel dimension C is 3 for RGB and 4 for RGBA. 

import numpy as np

# Create a blank 100×100 RGBA image (all zeros = transparent black)
img = np.zeros((100, 100, 4), dtype=np.uint8)

# Set pixel at (x=30, y=50) to opaque red
img[50, 30] = [255, 0, 0, 255]

# Set the entire red channel of a row to 128
img[25, :, 0] = 128python
Note
OpenGL and many GPU APIs use a different convention: the y-axis is flipped, with (0,0) at the bottom-left rather than the top-left. You will encounter this mismatch repeatedly when moving data between NumPy images and GPU textures.
01.04

Raster vs Vector Representations

Raster images store colors on a fixed grid. Vector images store instructions for drawing shapes: "draw a circle of radius 50 at position (100, 100), filled with blue." The rendering engine executes those instructions at display time.

Game engines work almost exclusively with raster images at runtime. Vector assets (SVGs, fonts) are rasterized — converted to pixel grids — before being sent to the GPU. Once on the GPU, everything is pixels.

01.05

Framebuffers and Drawing by Writing

A framebuffer is a region of memory that holds the pixel data for a single frame — what you see on screen right now. The display hardware reads this memory continuously, refreshing the screen at 60 or more times per second.

"Rendering" a game frame means writing pixel values into the framebuffer. There is nothing magical about it. The GPU executes programs (shaders) that calculate what color each pixel should be, writes those values into memory, and the display hardware reads them out.

Modern applications use at least two framebuffers: the front buffer (currently displayed) and the back buffer (currently being drawn into). When rendering is complete, the buffers are swapped. This prevents the user from seeing partial frames — a technique called double buffering. 

# Conceptually, every frame the GPU does something like this:
for y in range(height):
    for x in range(width):
        back_buffer[y, x] = compute_pixel_color(x, y, scene)

swap_buffers()  # back becomes front, front becomes backpython (pseudocode)
Note
In reality, GPUs evaluate thousands of pixels in parallel using shader programs. The simple nested loop above is the correct mental model, but not the execution model. The parallelism is why GPUs exist.
01.06

Practical Work

The exercises below build toward direct manipulation of pixel data. No image libraries are used for drawing — only NumPy array operations and Pillow for display output.

Exercise 1 · Create Images with Gradients

A gradient sets pixel brightness proportional to position. For a horizontal gradient: 

import numpy as np
from PIL import Image

W, H = 256, 256
img = np.zeros((H, W, 3), dtype=np.uint8)

# Horizontal gradient: red increases left → right
for x in range(W):
    img[:, x, 0] = x  # x goes 0..255, maps directly to red

# 2D gradient (more Pythonic using broadcasting)
xs = np.arange(W, dtype=np.uint8)
ys = np.arange(H, dtype=np.uint8)
img[:, :, 0] = xs[np.newaxis, :]   # red  = x
img[:, :, 1] = ys[:, np.newaxis]   # green = y

Image.fromarray(img).save("gradient.png")python

						Exercise 2 · Draw Shapes Using Pixel Math
					

					

						Drawing a circle without a graphics library means testing whether each pixel lies within
						the circle's equation: x² + y² ≤ r². This is exactly how GPU fragment shaders
						draw shapes.
					

					
import numpy as np
from PIL import Image

W, H = 256, 256
img = np.zeros((H, W, 3), dtype=np.uint8)

# Build coordinate grids (vectorized, no Python loops)
ys, xs = np.mgrid[0:H, 0:W]  # shape: (H, W) each

cx, cy, r = 128, 128, 80
dist_sq = (xs - cx)**2 + (ys - cy)**2

# Filled circle
img[dist_sq <= r**2] = [0, 229, 200]

# Ring (outline only)
ring = (dist_sq >= (r-2)**2) & (dist_sq <= r**2)
img[ring] = [255, 95, 58]python
